Backend dùng công nghệ gì, và vì sao chọn như vậy?

Django 5.2 (Python) có sẵn đăng nhập, phiên, trang quản trị và công cụ migration. Nhóm không phải tự viết lại những thứ dễ sai về bảo mật.

PostgreSQL 17 hỗ trợ khóa từng dòng khi nhiều người cùng sửa, ràng buộc dữ liệu và trigger viết bằng PL/pgSQL. psycopg 3 là thư viện để Python nói chuyện với PostgreSQL. gunicorn chạy Django trên máy chủ thật.

API viết bằng hàm view trả JsonResponse, không dùng Django REST Framework. Ít lớp trung gian thì người mới đọc code dễ hơn. Thư viện mới chỉ được thêm khi chủ dự án duyệt: cryptography để mã hóa email, Pillow để xử lý ảnh.

Frontend và backend nói chuyện với nhau như thế nào?

Frontend là ứng dụng React một trang (SPA). Mỗi khi cần dữ liệu, nó gọi một địa chỉ bắt đầu bằng /api/ bằng fetch, gửi và nhận JSON.

Sau khi đăng nhập, trình duyệt giữ cookie phiên sessionid và tự gửi kèm mọi yêu cầu. Yêu cầu ghi dữ liệu gửi thêm header X-CSRFToken (giải thích ở câu 46).

Frontend và API dùng cùng một tên miền, nên không cần mở CORS. Ở máy dev, Vite chuyển /api sang Django. Trên production, nginx chuyển /api sang gunicorn.

TypeScript · utils/api.ts
// frontend/src/utils/api.ts
export async function fetchApi(url: string, options: RequestInit = {}) {
  const headers = new Headers(options.headers || {});
  headers.set('X-CSRFToken', getCookie('csrftoken'));
  if (!(options.body instanceof FormData)) headers.set('Content-Type', 'application/json');
  const response = await fetch(url, { ...options, headers, credentials: 'include' });
  if (response.status === 401) window.dispatchEvent(new Event('session-expired'));
  return response;
}

Một yêu cầu từ trình duyệt đi qua những chặng nào trước khi chạm tới cơ sở dữ liệu?

Mỗi chặng có một việc riêng. Cloudflare lo HTTPS và chặn bớt tấn công. nginx phục vụ giao diện và chuyển API sang Django. Middleware của Django đọc phiên, kiểm tra CSRF và giới hạn tuổi phiên. Decorator kiểm tra quyền. View đọc dữ liệu gửi lên. Service làm nghiệp vụ trong transaction. PostgreSQL chặn lần cuối bằng ràng buộc và trigger.

Hiểu đường đi này thì gặp lỗi sẽ biết tìm ở đâu. Lỗi 403 có thể do thiếu CSRF (middleware) hoặc thiếu quyền (decorator). Lỗi 409 thường do service phát hiện xung đột.

Migration là gì, và có những quy tắc nào khi sửa bảng?

Migration là file mô tả từng bước thay đổi cấu trúc bảng, chạy theo thứ tự 0001 → 0021. Nhờ vậy DB ở máy dev và DB thật luôn được nâng cấp giống nhau.

DB cũ không nâng cấp được bình thường thì dùng lệnh sf_legacy_db_check để chẩn đoán trước khi xử lý.

Sổ kho StockTransaction là gì?

Mỗi lần tồn kho thay đổi, hệ thống ghi đúng một dòng vào sổ kho: loại IN (nhập), OUT (xuất) hoặc ADJUST (kiểm kê). Mỗi dòng có lượng thay đổi, đơn giá và giá trị.

Ví dụ: chốt phiếu nhập 13 kg thịt giá 135.000 đ/kg tạo một dòng IN với quantity_delta = 13.000 và value_delta = 1.755.000.

Sổ kho chỉ được ghi thêm, không sửa, không xóa. Muốn sửa sai thì ghi một bút toán mới (ví dụ kiểm kê). Đây là cách kế toán giữ được lịch sử.

        OUT = "OUT", "Xuất"
        ADJUST = "ADJUST", "Kiểm kê"
    food = models.ForeignKey(FoodItem, on_delete=models.PROTECT)
    type = models.CharField(max_length=6, choices=Type.choices)
    quantity_delta = models.DecimalField(max_digits=14, decimal_places=3)
    unit_cost = models.DecimalField(max_digits=14, decimal_places=2)
    value_delta = models.DecimalField(max_digits=28, decimal_places=2)

Mỗi loại số được lưu với bao nhiêu chữ số?

Số lượng: Decimal(14,3), tức chính xác tới 1 gram khi đơn vị là kg. Đơn giá: Decimal(14,2). Giá trị dòng: Decimal(28,2), đủ chỗ cho lượng lớn nhân đơn giá lớn.

Định lượng món cho một suất: Decimal(14,6), vì 0,4 g muối = 0.000400 kg. Nếu chỉ giữ 3 số lẻ, con số này thành 0 và 300 suất cũng ra 0. Đây là lỗi ISSUE-003 đã được sửa.

    0,4 g = 0.000400 kg không bị làm tròn thành 0 trước khi nhân số suất."""
    quantity = models.DecimalField(max_digits=14, decimal_places=6)

Làm tròn thế nào cho đúng?

Dự án luôn dùng quantize(..., ROUND_HALF_UP), tức làm tròn "5 lên" như học ở trường.

Không dùng hàm round() của Python, vì nó làm tròn kiểu ngân hàng: số đúng 0,5 được làm tròn về số chẵn gần nhất. Kết quả đó khác với cách kế toán của trường.

Python
>>> round(2.5), round(3.5)
(2, 4)                       # làm tròn về số chẵn: dễ gây lệch
from decimal import Decimal, ROUND_HALF_UP
def money(value):            # services.py
    return Decimal(value).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

Trigger là gì? Cho một ví dụ trong dự án.

Trigger là đoạn code chạy bên trong PostgreSQL, tự động mỗi khi có lệnh INSERT, UPDATE hoặc DELETE trên một bảng. Nó dùng để chặn những thay đổi trái luật.

Ví dụ: trigger của sổ kho chỉ cho thêm dòng mới, không cho sửa hay xóa. Có ai lén chạy UPDATE trực tiếp bằng SQL thì vẫn bị chặn.

SQL · migration 0006
CREATE FUNCTION sf19_protect_ledger() RETURNS trigger AS $$

Giá bình quân gia quyền được tính ra sao?

Nhu cầu nguyên liệu của một ngày được tính như thế nào?

Nhu cầu = tổng của (số suất × định lượng từng món). Cộng hết trước, làm tròn sau cùng tới 0,001 kg theo ROUND_HALF_UP. Đơn vị "cái" (trứng, hộp sữa chua) thì làm tròn lên, vì không mua được nửa quả trứng.

Từ nhu cầu, hệ thống đề xuất mua bao nhiêu?

    def __call__(self, request):
        user = getattr(request, "user", None)
        if user is not None and user.is_authenticated:
            now = timezone.now().timestamp()
            started = request.session.get(SESSION_AUTH_AT)
            if not isinstance(started, (int, float)):
                request.session[SESSION_AUTH_AT] = now
            elif now - started > settings.SESSION_ABSOLUTE_MAX_AGE:   # 12 giờ

HTTPS được xử lý ở đâu, và Django làm sao biết yêu cầu là HTTPS?

Cloudflare giữ chứng chỉ và mã hóa HTTPS với trình duyệt. Qua tunnel, Cloudflare gửi kèm header X-Forwarded-Proto: https; nginx chuyển tiếp header này. Django đọc nó qua SECURE_PROXY_SSL_HEADER, nhờ đó mới đặt cookie Secure và chuyển HTTP sang HTTPS.

HSTS báo trình duyệt "chỉ dùng HTTPS với trang này". Giá trị ban đầu thấp (3600 giây) và tăng dần khi ổn định; không bật preload vì rất khó rút lại.

Python · settings.py
SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")
SECURE_SSL_REDIRECT = True
SECURE_HSTS_SECONDS = int(os.getenv("SECURE_HSTS_SECONDS", "3600"))
SECURE_HSTS_PRELOAD = False
